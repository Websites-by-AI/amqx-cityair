## ۱) نقص محصول — `?lang=` در deep link گم می‌شد ❗️

**چطور پیدا شد:** آدرس `…/partners/index.html?lang=fa` را مستقیم باز کردم؛ صفحه **انگلیسی** بالا آمد
ولی لینک‌های داخل سایت (مثل `/?lang=fa#/partners`) درست کار می‌کردند.

**بازتولید (قبل از رفع):**

```
https://sosa123454321-amqx-cityair.static.hf.space/partners/index.html?lang=fa
→ redirect → /index.html#/partners?lang=fa      ← query داخل hash افتاده
→ location.search === ""  ⇒  lang=en ، dir=ltr  ❌
```

**ریشه:** اسکریپت کوچک «پیش از ری‌اکت» در `app/index.html` (همان که صفحهٔ ثابت هر مسیر را به
SPA می‌رساند) query را **بعد از hash** می‌گذاشت:

```js
// غلط
location.replace(location.origin + "/#" + path + location.search);
```

مرورگر هر چه بعد از `#` بیاید را بخشی از hash می‌داند، پس `location.search` خالی می‌ماند و
تشخیص زبان (که اول از `?lang` می‌خواند) به پیش‌فرض انگلیسی برمی‌گشت. همین اسکریپت در
**۳۵ صفحهٔ** آینهٔ Hugging Face و در `app/site/index.html` تکرار می‌شد، پس همهٔ deep link‌های
اشتراک‌گذاری‌شده با زبان فارسی/عربی/ترکی خطا داشتند (مسیر درست بود، فقط زبان غلط).

**رفع:**

```js
// درست — query باید قبل از hash بماند
location.replace(location.origin + "/" + location.search + "#" + path);
```

به‌علاوه در `app/src/i18n/index.tsx` تابع `langFromUrl()` اضافه شد که `?lang=` را
هم از query واقعی و **هم** از پشت `?` داخل hash می‌خواند (تا لینک‌های قدیمی که قبلاً
با همین باگ به اشتراک گذاشته شده‌اند هم درست باز شوند) و یک listener برای `hashchange`
(چون تغییر hash صفحه را دوباره بارگذاری نمی‌کند).

**تأیید (بعد از رفع):**

| محیط | آدرس | نتیجه |
| --- | --- | --- |
| آینهٔ HF | `/partners/index.html?lang=fa` | ✅ `lang=fa dir=rtl` ، URL نهایی `/?lang=fa#/partners` |
| آینهٔ HF | `/cities/istanbul/index.html?lang=ar` | ✅ `lang=ar dir=rtl` |
| آینهٔ HF | `/guidance/index.html?lang=tr` | ✅ `lang=tr dir=ltr` |
| آینهٔ HF | `/index.html#/partners?lang=fa` (لینک قدیمی) | ✅ `lang=fa dir=rtl` |
| سرور محلی | `/?lang=fa#/partners` و `/index.html?lang=tr#/cities/istanbul` | ✅ fa/rtl و tr/ltr |
| تست خودکار | بررسی تازهٔ شمارهٔ ۷۹ در `tools/e2e-test.py` | ✅ `lang=fa dir=rtl search='?lang=fa'` |

## ۲) نقص ابزار تست — نتیجهٔ گمراه‌کنندهٔ ۱۲/۲۰ در تست امنیتی

**چطور پیدا شد:** بعد از رفع بالا، `tools/security-test.mjs` را دوباره اجرا کردم و **۱۲/۲۰**
گزارش شد، در حالی که قبلاً ۲۰/۲۰ بود و سایت سالم کار می‌کرد.

**ریشه:** رمز ادمین از `ADMIN_PASSWORD` (env)، بعد `worker/.dev.vars` خوانده می‌شد. در نسخهٔ
سخت‌شدهٔ اخیر، فقط `ADMIN_PASSWORD_SHA256` و `ADMIN_PASSWORD_SALT` در `.dev.vars` مانده‌اند
(رمز خام عمداً حذف شده) — پس متغیر خالی می‌شد و همهٔ بررسی‌های وابسته به ورود، `HTTP 0`
می‌گرفتند: یک **شکست کاذب** به‌جای پیام روشن.

**رفع:** `security-test.mjs` حالا رمز را در آخرین مرحله از فایل خصوصی و
git-ignored `private-archive/PREVIEW-PIN.txt` می‌خواند و اگر هیچ‌کدام نبود، **به‌جای
اجرای تست‌های گمراه‌کننده، با پیام روشن خارج می‌شود** (`exit 2`).

```
GITHUB_TOKEN=… node tools/security-test.mjs http://127.0.0.1:8788
──── 20/20 security checks passed ────
```

(بررسی ۲۰ برای اسکن ریپوی GitHub به توکن نیاز دارد؛ بدون آن «skipped» می‌شود.)
