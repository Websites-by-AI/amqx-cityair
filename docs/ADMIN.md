# 🔐 راهنمای پنل ادمین و دیتابیس خصوصی

پنل ادمین جایی است که **مکاتبات و اطلاعات مهم پروژه** نگهداری می‌شود — بیرون از دید عموم.

| مورد | مقدار |
| --- | --- |
| آدرس پنل | `/` + `#/admin` (مثلاً `https://aqmx.atikova.com/#/admin`) |
| نام ادمین | `ann` |
| رمز فعلی | در `private-archive/PREVIEW-PIN.txt` (بیرون از گیت و بیرون از سایت) |
| عمر نشست | ۳۰ دقیقه، بعد از آن خودکار خارج می‌شوید |
| قفل ورود | بعد از ۵ تلاش ناموفق، ۱۵ دقیقه قفل (فقط برای همان IP) |

> ⚠️ **پیش از دیپلوی روی دامنه‌ی عمومی، رمز را عوض کنید.** رمز ۴ رقمی فقط ۱۰٬۰۰۰ حالت دارد؛
> محدودیت تلاش جلوی حمله‌ی آنلاین را می‌گیرد، ولی رمز بلند امن‌تر است:
>
> ```bash
> node tools/admin-pass.mjs "یک-رمز-بلند-و-تازه" --write      # محلی
> cd worker && npx wrangler secret put ADMIN_PASSWORD_SALT     # روی Cloudflare
> cd worker && npx wrangler secret put ADMIN_PASSWORD_SHA256
> ```
>
> رمز هیچ‌وقت در فایل‌ها ذخیره نمی‌شود؛ فقط هش نمک‌دار (`SHA-256(salt+password)`).

## داخل پنل چه چیزی هست؟

| تب | محتوا |
| --- | --- |
| **نامه‌ها** | متن کامل ۴ سند مکاتبه — پیام خانم Kolesnikova (کامل، شامل جمله‌ای که در خلاصه‌ی عمومی نیست)، ایمیل خروجی ۱۸:۴۶ با شماره‌ی واتساپ و هر سه لینک، متن فارسی یادداشت ژولیت، یادداشت COP31 |
| **تماس‌ها** | ۵ رکورد: Maria Kolesnikova، Mr. Muradyl، ژولیت (با برچسب UNVERIFIED)، تیم XPRIZE، و مالک پروژه. هر رکورد بخش «اطلاعات خصوصی (فقط اینجا)» دارد — کانال تماس ترجیحی، زبان، بهترین ساعت تماس، شماره‌ی واتساپ |
| **پیگیری‌ها** | ۸ تسک با مهلت و اولویت + فرم افزودن هر «اطلاعات مهم» تازه (هر نکته، لینک، شماره‌ی تماس) |
| **یادداشت‌های مهم** | ۵ یادداشت: قاعده‌ی انتشار، هشدار درباره‌ی «شریک متان» نبودن MoveGreen، خطر امنیتی رمز کوتاه، وضعیت متن دریافتی، خط پایه‌ی فنی XPRIZE |
| **گزارش دسترسی** | هر ورود، هر خواندن، هر خروج — با IP و زمان (۱۰۰ رکورد آخر) |

> رمز پیش‌نمایش عمداً داخل مخزن نیست: در `private-archive/PREVIEW-PIN.txt` است و تست امنیتی شماره ۱۸ بررسی می‌کند که این رمز در هیچ فایل مخزن تکرار نشده باشد.

بالای صفحه: دکمه‌ی **خروجی کامل JSON** (پشتیبان‌گیری از کل دیتابیس) و **بازخوانی**.

## چه چیزی **هرگز** به GitHub نمی‌رود؟

| مسیر | چرا |
| --- | --- |
| `private-archive/` | کل بایگانی خصوصی؛ در `.gitignore` است و اسکریپت push هم با `--exclude` بیرونش می‌گذارد |
| `worker/.dev.vars` | رمز و هش نمک‌دار |
| `worker/src/kb.json` (نسخه‌ی محلی) | فقط دانش عمومی — مشکلی ندارد |

> تاریخچه‌ی GitHub یک بار با `ORPHAN=1 bash tools/push-github.sh` پاک‌سازی شد تا بلاب‌های قدیمی
> هم پاک شوند. تست شماره ۲۰ همین را بررسی می‌کند.

## افزودن اطلاعات تازه (بدون برنامه‌نویسی)

1. وارد `#/admin` شوید.
2. تب **پیگیری‌ها** → فرم «افزودن پیگیری / اطلاعات مهم» → موضوع، مهلت، اولویت و متن → ذخیره.
3. یا در تب **نامه‌ها/تماس‌ها** متن را کپی و در بایگانی خصوصی ورک‌اسپیس (فایل `private-archive/admin-private.json`) نگه دارید
   تا با `node tools/seed-admin.mjs` در دیپلوی بعدی بازنشانی شود.

## دیپلوی روی Cloudflare

```bash
CLOUDFLARE_API_TOKEN="<توکن تازه>" CF_ACCOUNT_ID="88b6e2481cef2473409fdf549c56a54d" \
  TELEGRAM_BOT_TOKEN="<BOT_TOKEN_FROM_BOTFATHER>" \
  DOMAIN="aqmx.atikova.com" WITH_D1=1 WITH_KV=1 ADMIN_NAME="ann" \
  bash tools/deploy-cloudflare.sh
```

با `WITH_KV=1` یک namespace برای KV ساخته/وصل می‌شود و دیتابیس خصوصی **پایدار** می‌شود؛
بدون KV، داده فقط در حافظه‌ی همان instance می‌ماند (بعد از ری‌استارت پاک می‌شود و باید seed شود).
